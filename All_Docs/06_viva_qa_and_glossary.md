# FindZora: Viva Questions, Answers & Biometric Glossary

15. Viva Questions and Suggested Answers
Q1. What is the main purpose of FindZora?
FindZora helps a consenting attendee discover likely photographs of themselves inside an authorised event photo
collection.
Q2. Why do you process images when they are uploaded?
Face detection and embedding generation are computationally expensive. Precomputing the index avoids repeating
that work for every attendee search.
Q3. Does every search avoid AI processing?
No. The query selfie still needs face detection/alignment and embedding generation. The system avoids reprocessing
all original event photos; it searches their precomputed embeddings.
Q4. Why use embeddings instead of manually measuring eyes and nose?
A trained recognition model produces a compact numerical representation that captures learned identity features.
Landmarks mainly help locate and align facial features.
Q5. What if storage increases?
We separate original photo storage from embedding storage, store each original photo once, deduplicate uploads, use
compact vector formats and apply retention policies. Storage can scale independently.
Q6. Can you guarantee 100% accuracy?
No. Real-world images vary. We measure precision, recall and error rates, calibrate thresholds and present candidate
results for review.
Q7. Can the current system recognise someone from behind?
Not reliably with face recognition because the face is not visible. Back-view analysis is a future research direction
using non-face visual cues, but it cannot guarantee identity.
Q8. What if one lakh users use the system?
We would measure concurrency and workload, then scale API instances and background workers independently, use
queues, shared storage, event partitions and suitable vector infrastructure.
Q9. Why not store all embeddings in JSON files?
JSON is useful for interchange, but a database and vector index are better for metadata management and efficient
similarity search at scale.
Q10. Is a browser camera selfie proof of liveness?
No. Camera capture alone does not prevent photo or video spoofing. Liveness/anti-spoofing needs a separate
evaluated mechanism.
Q11. Why restrict search by event?
It reduces search scope and prevents attendees from searching unrelated collections or viewing photographs outside
their permission.

Q12. What is the future scope?
Multi-angle matching, hair and clothing cues, body silhouette, pose, top-view research, privacy-preserving processing
and advanced anti-spoofing—each subject to testing and privacy review.

16. Glossary
Term
Meaning
Face detection
Locating face regions in an image.
Facial landmarks
Key points such as eye, nose and mouth positions.
Face alignment
Normalising face crop/orientation before recognition.
Embedding
Numerical vector generated by a trained model.
Cosine similarity
A measure of how similar two vectors point in direction.
FAISS
A library for efficient similarity search over dense vectors.
Vector index
A data structure that supports fast nearest-neighbour search.
Background worker
A process that performs queued work outside the user request path.
Queue
A buffer that holds jobs until workers process them.
Precision
Fraction of returned matches that are correct.
Recall
Fraction of all true matches that were found.
False positive
An incorrect match returned by the system.
Person re-identification
Matching a person across images or cameras using visual cues.
Liveness / anti-spoofing
Methods intended to distinguish a live capture from a presentation attack.

Final project statement
FindZora's strength is its practical architecture: authorised event photos are processed
asynchronously, faces are represented by compact embeddings, and attendee searches compare
against a precomputed event index. The project aims for fast, measured and privacy-conscious
discovery—not a promise of perfect recognition. Advanced back-view, top-view and
appearance-based methods remain future research, not current functionality.
